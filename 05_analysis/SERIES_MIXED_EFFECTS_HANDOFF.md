## Task and agreed requirements

Build reusable modeling code that reads the **full series masters** already
generated by the Yeo2011 ROI or NIfTI PCA pipelines and fits:

```r
cgi_change ~ 1 + E + E:ef_sf + (1 | age) + (1 | sex)
```

`E` is one selected ROI field summary or one PCA component score derived from
the requested `field_name`, such as `magnE_mean`. Use the saved clinical,
stimulation, and feature columns. Do not rebuild the clinical cohort, load
NIfTI/mesh/HDF5 files, refit PCA, or repeat spatial extraction.

The user's continuing requirements are:

- Treat different treatment series as separate observations, including series
  from the same patient or series that reuse a simulation. Add no patient random
  effect or patient-clustered inference.
- Preserve the current separation by `model_type × step`. Also keep field,
  normalization, and PCA basis identities separate.
- Save every generated artifact under **`$RESULTS_DIR/<analysis_name>/`**.
  No generated data, fitted models, logs, caches, or plots belong in source code.
- Reuse existing code selectively. Some `simnibs_parcel_analysis` code is older
  or deprecated. Avoid copying whole runners and avoid a broad refactor during
  this task. Preserve unrelated working-tree changes.

Recommended first implementation: one model per feature per configuration,
matching the existing correlation workflow. A joint model containing multiple
PCs/ROIs is a separate scope decision, not implied by the equation above.

## Model semantics to preserve

The fixed design has exactly three columns: intercept, `E`, and `E * ef_sf`.
In a Patsy formula, write `E + E:ef_sf`. Writing `E * ef_sf` as formula shorthand
would also add an `ef_sf` main effect. Do not add that term, fixed age/sex terms,
baseline CGI, placement, session count, or an unrelated clinical null model.
See the [Patsy formula documentation](https://patsy.readthedocs.io/en/latest/formulas.html#operators).

The requested random effects are **literal crossed random intercepts** for each
distinct observed age value and each sex category. They are not continuous
fixed age adjustment or a patient intercept. Do not round or bin age or silently
replace the requested terms. These age/sex effects induce covariance between
rows sharing those categories; the independent-series instruction excludes
additional patient grouping, not the random effects explicitly requested here.

A construction already used in this repository is:

```python
model = smf.mixedlm(
    "cgi_change ~ 1 + E + E:ef_sf",
    data=series_rows,
    groups=np.ones(len(series_rows)),
    re_formula="0",
    vc_formula={"age": "0 + C(age)", "sex": "0 + C(sex)"},
    missing="raise",
)
```

The constant outer group and suppressed group intercept leave age and sex as
the two variance components. The implementation follows the
[Statsmodels crossed variance-component approach](https://www.statsmodels.org/stable/examples/notebooks/generated/variance_components.html#crossed-analysis).
Do not pass R's `(1 | ...)` syntax directly to the fixed-effect formula parser.

Keep supplied units by default. The conditional slope for `E` is
`beta_E + beta_interaction * ef_sf`; `beta_E` alone is the slope at `ef_sf = 0`.
Centering `ef_sf` reparameterizes that slope coefficient while preserving the
fixed-model column space because `E` is already included. Centering `E` can
change the model because an `ef_sf` main effect is absent. Do not introduce
centering or standardization without an explicit, recorded choice.

## Three important contracts in the current masters

1. **Use the saved outcome sign.** The current loader defines
   `cgi_change = cgi_start - cgi_end` in
   [`utils/loader.py`](simnibs_parcel_analysis/utils/loader.py), so positive change
   represents a reduction in CGI. Older `clinical.py` / course-model preparation
   uses the opposite subtraction. Consume saved `cgi_change` unchanged. Any
   consistency check against start/end must follow the current master convention.

2. **Use the saved factor from the representative session.**
   [`load_series_tables()`](networks/mni_yeo2011_prep_data.py) selects
   `session_num=2` and its loader computes
   `ef_sf = pulse_width_ms * frequency_hz * percent_charge`.
   This is not a course sum, mean, or mode, and the code treats it as a legacy
   stimulation index rather than measured physical charge. Construct the new
   interaction from the **same series row's `E` and `ef_sf`**. Do not import older
   session-aggregation rules or multiply by the factor twice.

3. **Use `age`, not `age_scan`.** Both may exist. The current series merge
   prefers the CGI/course-sheet `age`, `sex`, and `dob` when stimulation tables
   also contain them. The pipeline does not recalculate age. Preserve those
   columns and their provenance.

## Inputs and feature mapping

Read master CSVs, not correlation-result CSVs or plots' source extracts. The
master contains the observations and covariates needed for modeling. A saved
correlation p-value is not a p-value for this model.

| Input | Feature identity | Numeric value used as `E` | Observation key within a feature |
|---|---|---|---|
| Yeo2011 long master | `roi_org` (older tables may use `roi_name`) | `mean` by default | `person_id`, `series_num`, configuration |
| PCA long master | `basis_id`, `component` | `score` | `basis_id`, `sample_id` |
| PCA wide scores, optional later support | `basis_id` and a `PC...` column | That score column | `basis_id`, `sample_id` |

`field_name` identifies the source field; it is not necessarily the name of a
numeric column in these masters. For example, `field_name == "magnE_mean"`
still maps to ROI `mean` or PCA `score`. A PCA score is signed and is not a
regional physical field magnitude or a component-map weight. Negative scores
are valid and must remain in the model.

Required shared modeling columns are `person_id`, `series_num`, `model_type`,
`step`, `field_name`, `cgi_change`, `age`, `sex`, and `ef_sf`, plus the relevant
feature identity/value columns. Preserve all additional metadata in the prepared
model-input export. There is no need for a new demographics file when these
columns are present.

ROI details:

- Use the complete `roi_org` label, not `roi` alone; shortened labels are not
  unique across hemispheres/networks.
- The raw `mean` is already the ROI's spatial average. In a brain-normalized
  master, `mean = mean_raw / whole_brain_mean`; use this saved `mean` directly.
- Only `mean` is normalized by the current normalizer. Columns such as `p95`
  remain raw. Supporting another statistic requires explicit metric metadata;
  do not label it normalized just because the filename is normalized.
- The existing seven bilateral network features are arithmetic averages of
  member ROI means, with each ROI weighted equally. Network inclusion is
  optional scope, separate from the regional ROI requirement.

PCA details:

- Keep `basis_id`, `component`, `component_index`, variance columns, and
  `selected_for_correlation`. Parse Boolean selection values correctly from CSV.
- Whole-brain normalization happened **before PCA fitting** in the normalized
  analysis. Do not divide saved scores by brain means again.
- Never pool the same component number across different bases. `PC1` is a
  different fitted spatial axis in each model/step/normalization group.
- `data/series_inputs.csv` retains metadata but contains no PCA scores. Use the
  PC master for the first implementation.

Recommended PCA default: use components flagged `selected_for_correlation`,
with an explicit option to include all components or name components. Selection
must use saved flags, not a new outcome association or a newly applied variance
threshold. This default is a proposal, not an additional user decision already made.

## Data preparation and validation

Build two small source adapters that produce a common feature representation:
`feature_type`, `feature_id`, `E`, canonical normalization metadata, and the
original series columns. Both feed one shared model-fitting function.

Fit separately by `feature_type × field_name × normalization × model_type × step`
and feature identity; PCA additionally requires `basis_id`. Start with one master
per invocation to make raw/normalized analysis provenance explicit.

Before fitting:

- Reject missing or duplicate column names and ambiguous feature identities.
- Reject duplicate series/feature/configuration rows. Never average duplicate
  observations or deduplicate by `full_file_path` or `person_id` alone.
- Verify clinical/stimulation metadata agrees across the repeated feature rows
  for each series/configuration before selecting one metadata record.
- Keep one observation per series **within each fitted feature**. Long rows for
  different ROIs/PCs must not become additional observations in the same fit.
- Align joins and pivots by validated keys; never join covariates by row position.
- Require finite numeric outcome, `E`, `ef_sf`, and age; validate sex categories.
  Do not silently drop incomplete cases or impute values. If explicit exclusion
  support is added, export the excluded keys and reasons.
- Check the intercept/`E`/interaction design is finite and full rank, with more
  observations than fixed coefficients. A constant `ef_sf`, for example, makes
  the interaction collinear with `E`.
- Report age/sex level counts and group sizes. A single level is insufficient
  for either requested variance component; all-unique ages confound the age
  intercept variance with residual variance. Do not invent bins as a fallback.

The inspected groups have 35 series, 28 exact age levels, and two sex levels.
Many small age groups and few sex levels may produce weak or singular variance
estimates. Record the actual fit diagnostics and failures; do not silently fit a
different model when the requested one fails.

## Proposed implementation and outputs

A small new module/package such as `series_models/` can separate adapters,
fitting, and workflow code, with a thin `run_series_mixed_effects.py` entrypoint.
These names are proposals and do not exist as part of this task yet. Avoid
separate copied ROI and PCA model runners.

Suggested CLI options: `--master-path`, `--feature-type roi|pca`,
`--field-name`, `--analysis-name`, explicit feature selection, PCA selected/all
scope, and `--prepare-only`. A Slurm submission wrapper should create logs under
the results root before submission, following the current PCA/ROI pattern.
Use separate analysis names for distinct source/normalization runs or include
those identities in every output path so runs cannot overwrite each other.

Suggested artifacts under `$RESULTS_DIR/<analysis_name>/`:

```text
analysis.json                 # formula, inputs/hash, selection, versions, fit settings
data/model_input_long.csv     # full retained metadata, feature identity, E, E*ef_sf
coefficients.csv              # fixed effects per feature: estimate, SE, Wald z/p, 95% CI
fit_status.csv                # every planned feature, including failed fits
predictions.csv               # if implemented; label fixed-only vs conditional predictions
models/                       # optional serialized fits, with feature/basis identity
plots/                        # optional coefficient/interaction/diagnostic figures
logs/                         # Slurm logs and any plotting cache
```

All result rows need source type, field, normalization, model/step, feature
identity, PCA basis when applicable, source-master path/hash, and sample counts.
Save age/sex/residual variance estimates, log likelihood, AIC/BIC, convergence,
warnings, and explicit error messages. Age/sex variances must be finite and
nonnegative and residual variance finite and positive. Record zero-variance
boundary estimates separately; they do not alone prove invalid fixed-effect
covariance or Hessian inference. Label p-values/CIs as asymptotic normal Wald
inference, without a small-sample correction. Keep successful fits if another feature
fails and return nonzero after exporting the complete failure report. Invalid
inference must not look like a valid result with a missing warning.

Plots, serialized fits, multiplicity correction, joint feature models, null-model
comparisons, and permutation inference are follow-up scope choices. If BH
q-values are added, predeclare the family across features and coefficient terms,
save both raw p-values and q-values, and account explicitly for failed fits.
Do not reuse correlation permutation p-values as model inference.

## Verification and completion criteria for the next agent

Use small synthetic masters first. Meaningful checks should establish:

1. ROI/PCA adapters preserve all series metadata and align shuffled rows by keys;
   duplicate or conflicting records fail clearly.
2. Negative PCA scores survive unchanged, normalized features are not normalized
   again, and saved `cgi_change` retains the current start-minus-end sign.
3. The exact fixed design is `[1, E, E*ef_sf]`, with no extra factor main effect
   or patient/random group intercept. Verify the two crossed variance components.
4. Configurations, normalization modes, and PCA bases are never pooled; repeated
   patients remain distinct series, and feature repetition does not inflate n.
5. At least one actual synthetic crossed age/sex model fit recovers known fixed
   effects within an appropriate tolerance; also exercise collinear interaction,
   missing data, unidentifiable grouping, and optimizer/covariance failure paths.
6. Every requested fit has a status row, valid fits retain inference, and failed
   fits remain distinguishable. Every artifact stays in the selected results
   directory, including when environment/path configuration is invalid.

The old course-regression README advertises a crossed-model test file that is
absent in this checkout. Do not assume that model has current test coverage;
`tests/test_lmm.py` targets the different patient-intercept workflow.

After synthetic tests, a prepare-only pass on the existing masters can verify
keys, feature counts, metadata, factor provenance, and design rank before any
full fit. Do not submit real Slurm jobs as part of this handoff. Deliver the new
runner, reusable core, targeted tests, documentation, and concrete run commands
when the user assigns implementation to the next agent.
